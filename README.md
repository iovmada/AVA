# AVA Brebu

A static Romanian website for AVA Brebu. The site includes the homepage, pizzeria, restaurant and accommodation pages.

- [Figma homepage](https://www.figma.com/design/32nTqabvleQHyiAQThl7D4/Swissstaffing_local_DP?node-id=1597-2)
- [GitHub repository](https://github.com/iovmada/AVA)

## Local preview

Requires Node.js 18 or newer and no package installation.

```sh
npm run build
npm run dev
```

Open http://127.0.0.1:4173. Set `PORT` to use a different port.

The templates and menu data live in `site/`. Run `npm run build` after editing them to regenerate the HTML in `dist/`. CSS, browser JavaScript, fonts and images live directly in `dist/`.

## Hosting

Publish `dist/` as a static site. GitHub's `main` branch feeds the production DigitalOcean app at https://www.ava-brebu.ro. The full website is developed on `ava/full-website`; production currently serves the coming-soon page.

Before launch, confirm the proposed menu, room rates and hours, add the business's reservation and contact details, and complete the menu categories for which the design contains no listings.

## Menu approval

The editor lives at the unlisted address `/admin/`. Share the address and password with the restaurant owner. The public pages are built from `site/menu.json` and the photos in `dist/assets/site/`.

For a local walkthrough of the editor without a login, run `AVA_MENU_DEMO=1 npm run build` before starting the preview. The demo saves drafts in the browser. A normal `npm run build` produces the sign-in page. To test that login locally, set `AVA_MENU_LOCAL_PASSWORD` to a temporary password of at least 32 characters in the preview server's environment and use the `127.0.0.1` URL printed by the server. This local route uses the checked-out menu and does not submit to GitHub.

Enable live submissions when the full site is ready for production.

1. In the AVA GitHub repository, activate a branch ruleset for `main`. Require pull requests, one approving review, review from code owners, and renewed approval after new commits. Prevent force pushes and branch deletion. Keep the menu app off the bypass list. The reviewer is `@iovmada` in `.github/CODEOWNERS`.
2. Install a dedicated GitHub App on `iovmada/AVA` with **Contents** and **Pull requests** read and write permissions. Use the app identity for proposals so the reviewer can approve them from a separate GitHub account.
3. In DigitalOcean App Platform, deploy the Functions component from the `functions/` directory on `main` under route `/api`. Set the encrypted component variables `AVA_MENU_SUBMIT_CODE` (the editor password, such as the output of `openssl rand -hex 24`), `AVA_GITHUB_APP_ID`, `AVA_GITHUB_INSTALLATION_ID`, and `AVA_GITHUB_PRIVATE_KEY` (the PEM generated by GitHub, or its base64 encoding). Set `AVA_MENU_ORIGIN=https://www.ava-brebu.ro`. If both domain variants work, redirect the other one to this address so sign-in requests have the configured origin.
4. For the static site component, keep `main` as its source, enable automatic deploys, set the build command to `npm run build` and the output directory to `dist`. The editor calls `/api/menu/propose` by default.

The restaurant owner signs in with the editor password. Sessions expire after eight hours. Change the password in DigitalOcean to revoke existing sessions. After the owner submits a proposal, review **Files changed**, then approve and merge on GitHub to deploy the new menu. Restaurant photos are resized in the browser and committed alongside the proposed menu.

The separate approval preview builds with `npm run build:menu-review-preview` and publishes `menu-preview/`. Set `AVA_MENU_REVIEW_MODE=test` on its Functions component and set `AVA_MENU_ORIGIN` to the preview's HTTPS origin. That editor reads and opens pull requests against `ava/menu-review-test`, which needs the same required-review settings and code owners as production. For the production Functions component, set `AVA_MENU_REVIEW_MODE=production`.
